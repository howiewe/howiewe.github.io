## 待辦 A

**SSR 產品列表未解析圖片 JSON。**

- 證據：[主路由](../functions/[[path]].js) 將 D1 列直接傳給 [ProductListInjector](../functions/_lib/injectors.js)，注入器卻以物件陣列讀取 `imageUrls[0].url` 與 `size`。
- 已做隔離驗證：以符合現有儲存格式的 JSON 字串作為 D1 查詢結果，執行 `/catalog` 路由並擷取產品列表注入內容，得到 `src="undefined"` 與 `scale(NaN)`。未使用真實 D1 或瀏覽器。
- 影響：SSR 初次回應的列表圖片與比例不正確；瀏覽器透過已解析圖片的 API 重新渲染可能掩蓋問題。
- 下一步：統一資料交接處的解析，驗證正常、空值及無效 JSON，並比較 SSR 與瀏覽器輸出；尚未修正、review 或實機驗收。

## 待辦 B

**管理端與批次端的圖片／產品儲存失敗回饋不完整。**

- 證據：[admin-app.js](../js/admin/admin-app.js) 的 `uploadImage()` 失敗回傳 `null`，提交流程仍將其寫入圖片項目並清除新圖狀態；`saveProduct()` 捕捉錯誤後未向提交者傳達失敗，外層仍關閉編輯視窗。[batch-upload.js](../js/tools/batch-upload.js) 收集圖片上傳失敗結果後未阻止產品提交，而是過濾缺少 URL 的圖片。
- 影響：可能以不完整圖片資料繼續儲存，或失敗後關閉表單；圖片與 D1 無共同交易，可能留下未關聯物件。
- 下一步：先確認部分成功、重試及保留編輯內容的預期，再重現失敗情境；不可只改提示而假裝成功。現有證據為靜態呼叫鏈查證，未做實機失敗注入。

## 待辦 F

**SSR／前端輸出與 SEO 仍有缺口。**

- 靜態查證：[主路由](../functions/[[path]].js) 將分類描述直接組成 HTML 交給 `ContentInjector`；管理、批次、型錄及輪播等部分模板也未一致轉義資料。`StructuredDataInjector` 直接將 JSON 序列化內容插入 script。這些輸出需依情境驗證，尚未進行完整安全重現。
- `HeadRewriter` 追加 description，未移除靜態 HTML 同名標籤；首頁及大廳 canonical 取 `url.href`，可保留查詢參數。
- 下一步：分別核對輸入來源、信任邊界及預期文字／HTML 行為，補對應輸出保護與測試；SEO 去重與網址規範另驗證原始 HTML。尚未修改。

## 待辦 G

- 已做隔離驗證：以「運動用品」頂層及其「跳繩」子分類模擬主路由排除精選後的資料，注入結果沒有子分類卡片；未使用瀏覽器或真實資料。
- 下一步：確認精選區與網格應呈現哪些層級，再調整資料傳遞與篩選；尚未修正或實機驗收。
