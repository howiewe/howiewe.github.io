# 使用介面與內容

已確認的產品長期要求只有 [深淺色模式與手機、電腦響應式支援](../專案長期要求/介面與裝置.md)。本頁說明目前實作及限制，不把尚未達成的部分寫成保證。

## 主題與樣式

[base.css](../css/base.css) 定義共用顏色、陰影、圓角及字型；`body.dark-mode` 覆寫深色 token。各頁按責任載入版面、元件或頁面 CSS，具體分工見 [前端架構與 SSR](前端架構與SSR.md)。

- 首頁、大廳、目錄與管理頁由 [theme.js](../js/shared/theme.js) 讀取 `localStorage.theme`，預設淺色，切換時保存選擇。
- 批次建檔頁有自己的主題載入與切換邏輯。
- 型錄工具未載入主題控制器，也未主動套用已儲存的偏好；列印紙張區使用固定淺底樣式。工具介面與輸出紙張需分別考量，這個現況不代表長期要求已全面符合。

目前仍有固定色值、inline styles 與 JS 動態樣式；部分具有列印、條碼或遮罩的用途，不能一律當成可直接替換的主題色。涉及共用樣式時沿用語意 token，核對兩種主題；已知整理範圍見 [待辦 E](待辦.md#待辦-e)。

## 響應式與互動

首頁有手機選單與遮罩；目錄及後台在手機使用可切換的分類側欄，桌面保留左右分工。產品詳情包含輪播、縮圖與燈箱；管理表單、批次工作台及列印工具有各自的版面規則，不能由共用 base 樣式推定所有尺寸皆可用。

產品單欄／雙欄檢視使用 `localStorage.productView`，前後台目前共用這個 key。產品彈窗、瀏覽器返回、燈箱 hash 及分頁的狀態分工見 [前端架構與 SSR](前端架構與SSR.md)。

驗證需涵蓋桌面、手機及斷點附近的側欄、表單、彈窗與滾動；修改相關互動時也檢查鍵盤、焦點及可辨識名稱。現況未有完整無障礙驗證證據。

## 語系與文字

目前以繁體中文為主，部分品牌、精選分類標籤與識別文字使用英文；沒有語系切換、翻譯回退或統一文字資源機制。

靜態文字寫在 HTML，動態提示、按鈕與錯誤文字散在瀏覽器腳本、SSR 及 API。這與 [開發偏好](../開發偏好.md) 的文字資源原則有落差；後續涉及文字的實作需建立或沿用最小必要資源方式，不因單語而省略，也不為導入文件直接進行全站重構。產品名稱、分類與描述屬使用者管理的資料，不是要複製到翻譯表的固定 UI 文字。

## 狀態與回饋

目錄使用載入、空列表與讀取失敗文字；管理端使用 Toast、確認對話及提交時停用按鈕，批次頁另顯示配對與上傳進度。型錄工具先產生預覽，再開放 PDF 下載。這些回饋目前不完全一致，尤其管理端與批次端的失敗處理存在已知缺口，見 [待辦](待辦.md)。

圖片比例與顯示資料見 [資料庫與儲存](資料庫與儲存.md)，PDF 分頁、條碼及匯出流程見 [管理與批次工具](管理與批次工具.md)。
