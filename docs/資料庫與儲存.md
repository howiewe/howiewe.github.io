# 資料庫與儲存

D1 保存分類與產品，R2 保存圖片二進位檔案。資料處理入口為 [db.js](../functions/_lib/db.js)、[r2.js](../functions/_lib/r2.js)；SSR 也直接查詢 D1，見 [前端架構與 SSR](前端架構與SSR.md)。

## D1 資料意義

已對 Pages 生產綁定的 D1 唯讀查詢 `sqlite_schema`，核對目前兩表及索引；未讀取產品資料列。本機仍沒有建表或 migration 檔案，下表保存欄位意義，後續重建需另備可執行 Schema、資料及恢復流程。

| 資料表 | 欄位 | 意義 |
| --- | --- | --- |
| categories | `id`、`name` | 分類識別碼與名稱 |
| categories | `parentId` | 父分類識別碼，`null` 表示頂層；前端與 API 均以此建立階層 |
| categories | `sortOrder` | 同層排序；新增分類取同層最大值加一 |
| categories | `description` | 分類介紹與 SEO 描述 |
| products | `id`、`name` | 產品識別碼與名稱 |
| products | `sku`、`ean13` | 產品編號與條碼；一般儲存將空或未提供的 SKU 轉為 `null`，前端條碼預覽支援 12 或 13 位輸入，後端未統一驗證 |
| products | `price`、`description` | 價格與產品描述；不同展示位置對空值或零價的呈現仍有差異 |
| products | `categoryId` | 所屬分類識別碼，與分類樹、查詢及麵包屑串接 |
| products | `imageUrls` | 圖片 URL 與顯示比例的 JSON 字串 |
| 兩表 | `createdAt`、`updatedAt` | 由寫入程式產生的 ISO 時間字串，供排序與 Sitemap 使用 |

目前兩表的 `id` 都是 INTEGER 自增主鍵；`name`、`createdAt`、`updatedAt` 為 TEXT NOT NULL。分類 `parentId` 為可空 INTEGER，宣告參照 `categories(id)`；`sortOrder` 為 INTEGER NOT NULL DEFAULT 0。產品 `sku` 為可空 TEXT UNIQUE，有對應唯一索引；`price` 為 REAL DEFAULT 0；`categoryId` 為可空 INTEGER，宣告參照 `categories(id)`。其餘描述、條碼及圖片欄位為可空 TEXT。這裡核對的是 Schema 宣告，未另測外鍵執行狀態。

目前雲端 `products` 沒有 `imageSize` 欄位，程式也未讀寫該欄位；圖片比例存於 `imageUrls` 內各圖的 `size`。

## 圖片格式與跨端轉換

目前 D1 的 `imageUrls` 以 JSON 字串保存物件陣列，例如 `[{"url":"https://example.invalid/image.webp","size":90}]`；`url` 指向公開圖片，`size` 是展示時的縮放百分比。

- 一般產品編輯：瀏覽器上傳新圖片後，將 `{ url, size }` 陣列交給產品 API；後端以 `JSON.stringify()` 寫入 D1。
- 批次建立：瀏覽器傳 URL 字串陣列；後端為每張圖補 `size: 90` 後序列化。
- 產品 API 讀取：解析成物件陣列；無圖片或解析失敗時回傳空陣列。
- SSR 直接讀 D1，需自行處理解析；目前產品詳情與分類代表圖有解析，但產品列表尚有格式落差，見 [待辦 A](待辦.md#待辦-a)。

這是現有資料與呼叫端的相容契約，調整時要一併檢查一般編輯、批次建立、SSR、瀏覽器與型錄工具。

## R2 上傳與刪除

上傳端點把 Request Body 寫入 `IMAGE_BUCKET`，以傳入的 Content-Type 作為物件中繼資料，回傳 `R2_PUBLIC_URL` 前綴加上物件 key 的公開 URL。公開讀取與 PDF 擷取圖片所需的 CORS 屬部署環境設定，見 [建置、驗證與運維](建置驗證與運維.md)。

更新產品時先比對新舊 URL，D1 更新完成後以 `await` 嘗試刪除被移除的舊 R2 圖片；刪除產品也先刪 D1 記錄，再解析並清理圖片。清理函式依公開 URL 前綴找出 key，捕捉 R2 刪除失敗並記錄，不回滾 D1。若圖片 JSON 無法解析，產品刪除回應會說明無法清理。

這套機制只涵蓋更新及刪除產品時已關聯的圖片，不是全 Bucket 的孤兒掃描；圖片上傳與產品寫入也沒有跨 D1/R2 交易，寫入失敗可能留下未關聯物件。
