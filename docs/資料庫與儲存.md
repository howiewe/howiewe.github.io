# 資料庫與儲存

本專案使用 **Cloudflare D1 (分散式 SQLite)** 儲存結構化關聯資料，使用 **Cloudflare R2** 儲存圖片檔案。

---

## 1. D1 資料庫結構 (Schema)

### `categories` 分類表
支援樹狀階層（透過 `parentId` 自關聯）。

| 欄位 | 型態 | 說明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 分類唯一識別碼 |
| `name` | TEXT NOT NULL | 分類名稱 |
| `parentId` | INTEGER | 父分類 ID（`NULL` 表示頂層母分類） |
| `sortOrder` | INTEGER NOT NULL DEFAULT 0 | 排序順序（數字越小排越前） |
| `description`| TEXT | 分類描述（用於 SEO meta description 與分類介紹） |
| `createdAt` | TEXT NOT NULL | 建立時間（ISO 8601 格式字串） |
| `updatedAt` | TEXT NOT NULL | 更新時間（ISO 8601 格式字串） |

### `products` 產品表
儲存產品規格、價格、條碼與圖片關聯。

| 欄位 | 型態 | 說明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 產品唯一識別碼 |
| `sku` | TEXT UNIQUE | 產品編號（SKU，可為 NULL） |
| `name` | TEXT NOT NULL | 產品名稱 |
| `ean13` | TEXT | EAN-13 國際條碼（12 或 13 位數字） |
| `price` | REAL DEFAULT 0 | 產品價格 |
| `description`| TEXT | 產品詳細描述 |
| `imageUrls` | TEXT | 圖片資料 **JSON 字串**：`[{"url":"...","size":90}]` |
| `imageSize` | INTEGER DEFAULT 90 | 已廢棄欄位（保留向下相容，以 imageUrls 內各圖 size 為準） |
| `categoryId` | INTEGER | 所屬分類 ID（外鍵關聯 `categories(id)`） |
| `createdAt` | TEXT NOT NULL | 建立時間（ISO 8601 格式字串） |
| `updatedAt` | TEXT NOT NULL | 更新時間（ISO 8601 格式字串） |

> **重要原則**：
> `imageUrls` 欄位儲存的是 **JSON 陣列字串**。後端讀取必須 `JSON.parse()`，寫入必須 `JSON.stringify()`。

---

## 2. R2 圖片儲存與孤兒檔案清理機制

- **上傳路徑**：圖片經由 `/api/upload/:filename` 直接寫入 R2 Bucket（`IMAGE_BUCKET`）。
- **公開 URL**：圖片外鏈由 `R2_PUBLIC_URL` 前綴加上檔案 Key 組成。
- **孤兒檔案自動清理**：
  - 當管理者更新產品圖片時，後端會比對舊圖片清單與新圖片清單。
  - 不存在於新清單中的舊 R2 圖片，會在資料庫更新成功後以非同步方式自動向 R2 發送刪除請求（`IMAGE_BUCKET.delete(keys)`）。
  - 當管理者刪除產品時，關聯的 R2 圖片亦會同步清理。
