# 05 前台查詢與產品呈現

狀態：未開始修正。基準與既有驗證限制見 [待辦索引](待辦.md)。

## 問題與影響

| 問題 | 發生條件與使用者影響 |
| --- | --- |
| 含句點的產品直連顯示首頁 | 主路由把路徑中任何句點都當成靜態資源而略過 SSR。站內點卡片正常，分享網址或重新整理仍可能錯誤。 |
| 不存在的產品沒有正確回報 | SSR 找不到產品時仍往一般產品列表流程走，回傳全部產品內容及 200；訪客與搜尋引擎難以判斷產品不存在。 |
| 初始圖片資料格式錯誤 | D1 的圖片欄位是 JSON 字串，SSR 列表卻直接當物件陣列讀取，產生錯誤圖片網址與比例；API 重畫後可能掩蓋問題。 |
| 未定價顯示不一致 | 產品列表與詳情對空價格的處理不同，詳情可能顯示 `$null`。 |
| 較舊結果覆蓋新條件 | 快速搜尋或切換分類／排序，先發出的請求較晚回來時，仍可改寫列表與分頁狀態。 |
| 分頁事件持續累加 | 每次重畫分頁都在同一個容器新增點擊監聽器，可能重複導覽或請求。 |
| 搜尋引擎描述與網址不一致 | SSR 追加 description 卻保留靜態同名標籤；首頁與大廳 canonical 使用完整請求網址，可能帶入查詢參數。 |

## 目標與待確認

- 相同產品在直接開啟、重新整理、站內瀏覽及 SSR／瀏覽器載入後，維持正確且一致的內容。
- 列表反映最後一次有效操作；一個分頁點擊只產生預期的導覽處理，空列表與失敗也不被過期結果覆蓋。
- 不存在的產品應有可辨識的找不到結果與相應 HTTP 狀態。空價格要隱藏、顯示詢價或其他文字，需先確認；canonical 的參數保留規則亦需核對用途。

## 證據與相關入口

- [SSR 主路由](../../functions/[[path]].js)：靜態資源判斷、產品直連、列表資料及 canonical；[注入器](../../functions/_lib/injectors.js)：`ProductListInjector`、`HeadRewriter`；[SEO 工具](../../functions/_lib/seo.js)。
- [前台程式](../../js/customer/customer-app.js)：`fetchProducts()`、`renderPagination()`、路由及產品詳情；對照 [資料層](../../functions/_lib/db.js) 的圖片解析與 [目錄頁](../../catalog.html) 靜態描述。
- 前次線上公開站曾重現「瑜珈磚 大. 小.」直連顯示首頁及空價格顯示 `$null`。該產品資料與網址可能日後改變，接手時應另用可控制的測試產品核對。
- 既有隔離路由檢查以圖片 JSON 字串重現 `src="undefined"`、`scale(NaN)`，並核對不存在產品回應；隔離事件與請求先後檢查重現分頁重複註冊及舊結果覆蓋新結果。前次正常公開瀏覽涵蓋搜尋、彈窗、燈箱返回與關閉恢復分類，不代表所有競態與直連皆已驗證。
- 本次整理核對上述程式入口，未重跑線上或隔離行為檢查。安全輸出本身集中在 [輸出安全與存取保護](01-輸出安全與存取保護.md)。

## 建議方向

釐清靜態資源與產品路由的判斷、圖片資料交接與價格呈現；讓過期請求無法提交結果，並使事件綁定不隨重畫累加。SEO 對照原始 HTML 修正，不只看瀏覽器重畫後的畫面。實際採取消請求、版本識別或其他方式，由接手者選擇。

## 完成條件

- 含句點等合法名稱的產品可直連與重新整理；不存在產品不再冒充正常全部產品頁。
- 正常、空值及無效圖片 JSON 有合理結果，SSR 與 API 載入後的產品內容一致，空價格符合確認後的規則。
- 以可控制的回應順序驗證快速切換，最後結果、分頁與條件一致；多次重畫後不增加重複點擊處理。
- 原始 HTML 的 description 與 canonical 符合確認後的規則；搜尋、返回、彈窗與燈箱的既有正常動線維持可用。
