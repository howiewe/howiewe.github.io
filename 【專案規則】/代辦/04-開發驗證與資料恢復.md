# 04 開發驗證與資料恢復

狀態：已有安全與管理入口的局部隔離回歸環境；完整環境重建、預覽及資料恢復範圍仍待確認與實作。基準見 [待辦索引](待辦.md)。

本項可與前幾項同步準備，尤其資料寫入與清理的驗證需要先有隔離資料及恢復方式，不必等所有較高編號項目完成才開始。

## 問題與影響

- 儲存庫尚缺一般開發／正式環境的綁定配置、正式 migration 與完整資料來源；已有的測試配置及最小建表／測試列只供局部回歸，安裝依賴後仍不足以重建完整系統。
- 既有雲端核對顯示預覽環境缺少完整 D1、R2 與環境變數，不能直接假設預覽站等同正式站。
- 沒有收錄可操作的備份、還原與恢復流程；圖片與資料分開保存，故障後不能只靠還原其中一邊判定已恢復。
- 已有自動單位／瀏覽器測試及 Functions 編譯入口，但保護範圍尚未涵蓋其他待辦的失敗、重試與恢復需求。沿用既有回歸環境並補足實際缺口，不能以語法或局部測試通過代替完整系統驗證。

## 目標與待確認

- 為已授權修正提供可重跑、可隔離且能判斷結果的驗證方式，讓維護者知道如何啟動及恢復必要資料。
- 需先確認本機與預覽各自要支援哪些功能、使用何種隔離資源，以及恢復流程的涵蓋範圍；本待辦不代表授權直接改雲端設定或正式資料。
- 測試依實際修正風險補足，並非要求先全面導入大型框架或 CI 才能修 bug。

## 證據與驗證缺口

- 入口為 [package.json](../../package.json)、[依賴鎖定檔](../../package-lock.json)、[建置與運維文件](../docs/建置、驗證與運維/建置驗證與運維.md) 及 [資料庫文件](../docs/功能、資料與契約/資料庫與儲存.md)。
- 舊待辦曾核對 Pages 來源、生產／預覽綁定、D1 兩表與索引、Access 及 R2 CORS；設定細節留在正式文件，不複製到待辦。當時 D1 只查 Schema 中繼資料，回應為 `rows_written: 0`、`changed_db: false`。
- 前次分析完成 21 份自有 JS 與首頁內嵌腳本語法檢查、文件與頁面引用檢查，以及部分隔離／SQLite 與線上公開瀏覽。這些是既有分析證據，本次文件整理不等於重新驗證。
- 目前可沿用的隔離環境、已通過項目、部署與使用者驗收證據集中見 [建置與運維文件](../docs/建置、驗證與運維/建置驗證與運維.md)。這些證據涵蓋安全輸出、管理登入與本機正常 API 操作，並未完成本項要求的真實 D1／R2 備份、清理失敗與恢復，以及完整大批 PDF 成品驗證；其餘範圍接手時依變動補查。

## 建議方向

先從目前 Schema 與必要綁定準備最小可用的隔離環境、可重建資料及恢復步驟；沿各項修正建立有意義的回歸保護。現有雲端設定需先核對再調整，不從文件推定仍完全相同。

## 完成條件

- 在約定支援的環境，維護者能依文件建立、啟動及重置測試系統，無須依賴未記錄的臨時操作。
- 必要資料與圖片恢復流程在隔離資源上驗證，能說明恢復範圍與限制。
- 關鍵正常、失敗與重試流程有可重跑的檢查；替身、實際服務、瀏覽器及使用者驗收的證據分清楚，缺項如實保留。

頁面存取契約見 [API 與安全保護](../docs/功能、資料與契約/API與安全保護.md)，現有隔離環境不應另建可繞過正式登入驗證的開關。
