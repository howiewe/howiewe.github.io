# 01 輸出安全與存取保護

狀態：已授權進行；本次任務的決策、固定起始基準及接續入口見 [目前交接](../交接/目前交接.md)。以下保留原始問題與完成條件，正式現況於同步時更新。

## 問題與影響

- 分類描述在伺服器產生網頁時，直接被當成 HTML；瀏覽器重新載入資料後卻以文字處理。同一份描述在兩個階段的安全處理不同。
- JSON-LD 雖然經過 JSON 序列化，仍直接放入 script 標籤，沒有處理可能提早結束標籤的內容。部分管理、批次、型錄及輪播模板，也沒有一致處理插入的資料。
- 因此特定資料可能改變網頁結構，存在儲存型 XSS 風險；不能因資料由管理者輸入，就認定所有輸出情境都安全。
- 既有 Access 設定涵蓋管理主頁與管理 API，但未涵蓋批次建檔及型錄工具頁。工具頁可開啟不等於管理 API 可未授權讀寫，兩者需要分開判斷。

## 目標與待確認

- 不讓產品、分類或錯誤資料意外變成可執行內容；正常名稱、換行及圖片仍能使用。
- 描述應只支援純文字，還是允許特定 HTML，需先確認，不能直接把目前任一端當成需求。
- 工具頁是否也必須登入才能開啟，需由使用者確認；不要自行擴大或取消頁面保護。

## 證據與相關入口

- [SSR 主路由](../../functions/[[path]].js) 的分類描述、[注入器](../../functions/_lib/injectors.js) 的 `ContentInjector` 與 `StructuredDataInjector`，以及 [SEO 輸出](../../functions/_lib/seo.js)。瀏覽器模板入口包括 [管理端](../../js/admin/admin-app.js)、[批次端](../../js/tools/batch-upload.js)、[型錄端](../../js/tools/print-catalog.js) 與 [輪播](../../js/customer/slider.js)。
- 前次分析曾以隔離輸出確認描述及 JSON-LD 的結束標籤風險，沒有在正式站放入攻擊資料，也未完成所有模板的瀏覽器執行重現。本次整理核對程式入口，未重跑安全測試。
- 既有雲端策略查證在 [API 與安全保護](../docs/功能、資料與契約/API與安全保護.md)。前次公開站檢查可開啟兩個工具頁、管理頁導向登入；登入後流程及雲端設定本輪未重新驗證。

## 建議方向

先分清文字、HTML、屬性、網址與 JSON-LD 的輸出情境，沿用適用工具並補足缺口；不要把單一轉義函式當成所有情境的解法。頁面登入範圍確認後，再核對 Access 與 API 的實際保護效果。

## 完成條件

- 對應情境中的特殊字元及結束標籤資料，不會插入非預期元素或執行程式，正常內容仍正確顯示。
- 相關 SSR 與瀏覽器模板都有必要驗證，不能只驗一個輸出點就宣稱全站安全。
- 頁面保護決策有明確記錄，未登入與已登入的頁面／API 行為符合決策；未能實測的部分明確保留。

SEO 的描述去重與網址規範另見 [前台查詢與產品呈現](05-前台查詢與產品呈現.md)。
