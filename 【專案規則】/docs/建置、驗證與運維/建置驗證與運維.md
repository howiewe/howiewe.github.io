# 建置、驗證與運維

## 本機入口與依賴

[package.json](../../../package.json) 的 `npm run dev` 執行 `wrangler pages dev .`，以專案根目錄作為靜態資源及 Functions 入口；另提供完整、單位與瀏覽器測試命令。使用能執行鎖定工具的 Node.js/npm 環境，先以 `npm ci` 安裝 [package-lock.json](../../../package-lock.json) 內的完整依賴。已驗證的本機環境為 Node.js 24、Windows 與 Microsoft Edge。

瀏覽器函式庫由 `vendor/` 本地引用，包括裁切、排序、CSV 解析、條碼、畫面擷取及 PDF 匯出；部分頁面另依賴 Google Fonts，圖片也使用外部公開 URL。這是目前依賴狀態，沒有新增零外部依賴的長期限制。

Functions 使用 `jose` 驗證登入憑證；Playwright 是本機回歸測試依賴。套件用途與版本以 package 檔案為準，安裝完整開發依賴與正式部署依賴的命令不要混用。

## 環境與部署

| 綁定 | 用途 |
| --- | --- |
| `D1_DB` | 產品、分類、SSR 與 Sitemap 查詢 |
| `IMAGE_BUCKET` | R2 圖片上傳及清理 |
| `R2_PUBLIC_URL` | 上傳回應的圖片 URL 前綴，以及清理時識別 R2 key |
| `ASSETS` | SSR 取得靜態 HTML 模板 |

這些值由 Functions 執行環境提供。管理 API、公開 API 與 SSR 的環境檢查及失敗行為見 [API 與安全保護](../功能、資料與契約/API與安全保護.md)、[前端架構與 SSR](../架構與設計/前端架構與SSR.md)。

Pages 的資源位置見下方 [Cloudflare 資源與接手檢查](#cloudflare-資源與接手檢查)，來源連接 GitHub `howiewe/howiewe.github.io` 的 `main`。Cloudflare 建置指令為 `npm ci --omit=dev --ignore-scripts --no-audit --no-fund`，根目錄及輸出目錄欄位維持空值，沿用專案根目錄資產與 Functions 的 Git 部署入口。

依賴安裝須在 Cloudflare 自動打包 Functions 前完成；空白建置指令曾讓新增的 `jose` 無法解析，導致部署失敗並保留舊版網站。`--ignore-scripts` 適用於目前的安裝需求；若未來加入依賴安裝腳本的建置工具，需重新評估這個選項。Push 完成後仍須確認部署成功及正式站實際使用的 commit，不能只看本機編譯。

生產環境的 D1／R2 資源對應見下表，公開圖片前綴由 `R2_PUBLIC_URL` 提供。另有 `AUTH_DOMAIN`、`POLICY_AUD` 環境變數，但目前程式沒有引用；實際登入識別來源及變更方式見 [API 與安全保護](../功能、資料與契約/API與安全保護.md)。預覽設定沒有列出對應的 D1、R2 與環境變數，不能假設預覽可提供完整功能。

儲存庫尚無一般開發／正式環境的 Wrangler 配置、正式 D1 migration、Access allow 名單配置或發布腳本／CI。測試啟動器只會產生專用的本機配置與測試 Schema，不是正式資料的備份或完整環境重建工具。因此單純執行開發指令不能還原完整系統，相關缺項見 [開發驗證與資料恢復](../../代辦/04-開發驗證與資料恢復.md)。

管理區與部署別名的保護方式見 [API 與安全保護](../功能、資料與契約/API與安全保護.md)。既有 R2 CORS 核對為允許 `https://kwanghwatw.pages.dev` 與 `http://localhost:3000` 的 GET／HEAD；本機改用其他開發來源時，不能假設正式圖片可供 PDF 擷取。隔離測試使用自己的同源圖片，不能代替真實 Bucket 的 CORS 或恢復驗證。

`robots.txt` 是爬蟲指示，不能代替存取保護；其中 Sitemap 使用既有 Pages 網域，換網域時需與 Sitemap、canonical、Access 及資源來源一併核對。

## Cloudflare 資源與接手檢查

本節提供 [Cloudflare 接手與查證長期要求](../../專案長期要求/Cloudflare接手與查證.md) 的實測入口。帳號 ID 為 `5a59f8f80492e27ff5a01a4ed17ff57d`，可由 [Cloudflare 後台](https://dash.cloudflare.com/5a59f8f80492e27ff5a01a4ed17ff57d) 定位；使用 MCP 時明確指定該帳號，不直接選第一個可見帳號。服務清單需對照文件、程式依賴及實際綁定維護，新增或搬移資源時更新此處。

下表 API 路徑共用 `/accounts/{account_id}` 前綴；資源識別取自本表或當次 API 回應，不從公開網域猜測帳號 ID。

| 服務 | 本專案資源 | 最小唯讀檢查 |
| --- | --- | --- |
| Pages／Functions | 專案 `kwanghwatw`，網域 `kwanghwatw.pages.dev`；Functions 隨同一專案部署 | `GET /pages/projects/{project_name}`：核對 Functions、建置、正式／預覽綁定與 `canonical_deployment`；再用當次部署 ID 讀取 `GET /pages/projects/{project_name}/deployments/{deployment_id}/history/logs` |
| D1 | 生產 `D1_DB` → `product-catalog`，ID `7c629a5d-d22a-4e60-bdfb-e2cafa0fa846` | `GET /d1/database/{database_id}`，再以 `/query` 執行最小 Schema SELECT，確認查詢層級可讀 |
| R2 | 生產 `IMAGE_BUCKET` → Bucket `menu-images` | `GET /r2/buckets/{bucket_name}` 與同路徑的 `/cors`，確認 Bucket 及相關設定可讀 |
| Access | 管理應用 `admin Panel`，ID `feb6f172-6e03-4491-9ede-7b14d179612b`；保護契約見 [API 與安全保護](../功能、資料與契約/API與安全保護.md) | `GET /access/apps/{app_id}` 與同路徑的 `/policies`，核對目標及策略 |
| Cloudflare Images 來源 | [SSR 主路由](../../../functions/[[path]].js) 的 `defaultImage` 指向 `imagedelivery.net`；圖片 ID／網址以該來源為準，管理帳號歸屬尚未確認 | 從該來源取得圖片 ID，以 `GET /images/v1/{image_id}` 查定位；目前在上述帳號回傳 404，須明列未確認，不能視為已讀到該資源 |

執行時先用 MCP 的 `whoami` 及 `GET /accounts` 確認連線身分與帳號存取，再逐項完成表內檢查。D1 `/query` 使用 HTTP POST，但只送唯讀 SQL，例如 `SELECT name,type FROM sqlite_schema WHERE name IN ('categories','products')`；不讀整批產品資料、不執行 DDL／DML，並確認回應沒有寫入或變更資料庫。其他項目失敗時，仍完成不受影響的唯讀檢查。

回報每項資源、已實測範圍、可讀／部分可讀／無法讀取／未確認，以及必要原因。工具不存在、401／403、404、網路失敗或不支援操作須分清楚；舊紀錄不能當成當次結果。R2 設定可讀不代表物件清單／內容可讀，公開圖片或網站可開啟也不代表 MCP 管理 API 已接通；任務需要更深讀取時另行查證，不以新增、修改、刪除資源測權限。文件不保存憑證或私密環境變數值。

## 驗證方式

### 自動檢查與隔離環境

| 入口 | 範圍 |
| --- | --- |
| `npm test` | 先執行單位測試，再執行瀏覽器整合 |
| `npm run test:unit` | 登入憑證、寫入來源與輸出工具的正常／失敗情境 |
| `npm run test:browser` | 實際本機 Functions、D1/R2 模擬環境與瀏覽器操作 |
| `npx wrangler pages functions build functions --outdir .wrangler/production-build` | 獨立檢查 Functions 是否能編譯；不發布網站 |

[測試啟動器](../../../tests/server.mjs) 每次在 `.wrangler/security-test-*` 建立資產與 Functions 的副本，使用 [測試資料](../../../tests/fixtures.mjs) 建立本機 D1，並啟動本機 R2 綁定。這些資源使用測試名稱與識別碼，不連接正式 D1/R2；每次重新建立資料，既有正式資料不會被重置。

測試服務使用 `127.0.0.1:8790`，測試用簽章／公開金鑰服務使用 `127.0.0.1:8791`，兩個連接埠須可用。每次產生的登入私鑰只在測試程序記憶體內；只有隔離副本的 Access 設定會信任該金鑰，正式程式沒有測試登入的繞過開關。瀏覽器測試以這些簽章驗證實際 middleware，再操作頁面與本機 API。

[Playwright 設定](../../../playwright.config.cjs) 在 Windows 預設使用已安裝的 Edge，其他平台預設 Chromium，需先備妥對應瀏覽器；可用 `TEST_BROWSER_CHANNEL` 指定通道。結果、失敗 trace 及管理頁截圖位於 `.wrangler/`。完整測試需要開發依賴，因此不能只安裝 `--omit=dev` 的套件。這套環境只供目前回歸範圍，不提供完整預覽部署、正式資料還原或通用手動開發環境。

### 適用的補充檢查

目前沒有 lint 或獨立的產品靜態建置腳本。按影響範圍補足必要檢查，不把自動測試範圍外的行為宣稱為已通過。

- 文件／規則：核對本地引用、導覽、需求與現況的區分、已知問題的保存，以及相對起始基準的完整修改範圍；可用 `git diff --check` 檢查空白問題，新文件也要納入檢查。
- JS 語法：在 PowerShell 可將 `Get-Content -Raw -LiteralPath '檔案路徑'` 管線送入 `node --input-type=module --check`；HTML 內嵌腳本需另行檢查。語法通過不證明資料或瀏覽器行為正確。
- API／資料：在已具備 Schema 與測試資料的隔離環境檢查分類階層、查詢回應、圖片轉換、正常及失敗的產品寫入與刪除；使用替身的單位檢查不能宣稱驗證了真實 D1/R2。
- SSR／瀏覽器：檢查首頁、大廳、全產品、分類與產品直連；比較原始 SSR HTML 與 JS 載入後結果，並驗證搜尋、排序、分頁、彈窗關閉及返回。
- 管理／工具：在測試資料範圍確認編輯、分類刪除限制、圖片裁切與上傳失敗、CSV 配對與建檔；型錄檢查分類選取、筆數、長名稱、圖片、條碼、換頁及 PDF 輸出。
- 介面：按 [使用介面與內容](../使用介面與內容/使用介面與內容.md) 核對兩種主題、手機與桌面、斷點及必要鍵盤互動。

程式驗證與使用者實機驗收的權責依 [Agent 工作規則](../../../AGENTS.md)；純文件工作不要求使用者替代技術核對。上述為入口與檢查範圍，不代表已全部執行。

## 維護與故障定位

先按錯誤所在層檢查環境綁定、API 回應、Functions 日誌與瀏覽器訊息。SSR 查詢失敗可能仍回傳靜態模板；R2 清理失敗也不回滾 D1，不能只看 HTTP 成功就判定整條資料流完成。

Sitemap 的回應設定共享快取一天，抓取分類或產品失敗時可能仍輸出部分結果；需檢查內容及日誌。產品更新沒有額外的全站快取失效流程。本機未收錄備份、還原、監控或孤兒圖片掃描工具，必要操作需先核對既有雲端配置與資料恢復方式。
