# 開發規範

通用開發方式見 [開發偏好](../../開發偏好.md)，工作流程見 [AGENTS.md](../../../AGENTS.md)。本頁說明目前程式的擴充入口與使用方式，不把現有技術選擇列為新的長期要求。

## 沿資料流定位修改

- 公開瀏覽：HTML 模板 → [SSR 主路由](../../../functions/[[path]].js) 與 [注入器](../../../functions/_lib/injectors.js) → [瀏覽器控制器](../../../js/customer/customer-app.js) → [公開 API](../功能、資料與契約/API與安全保護.md)。同一畫面可能同時有 SSR 與瀏覽器兩份呈現邏輯，修改時核對兩端的資料型別與可見結果。
- 管理與工具：先查 [管理與批次工具](../功能、資料與契約/管理與批次工具.md)，再沿頁面腳本、管理路由及 D1/R2 追查；上傳圖片與儲存產品是不同請求，成功與失敗狀態需分別處理。
- 共同資料：分類的父子關係、圖片格式、API 回應等契約集中於 [資料庫與儲存](../功能、資料與契約/資料庫與儲存.md) 與 [API 與安全保護](../功能、資料與契約/API與安全保護.md)，不在各端另寫互相矛盾的規格。

## 模組與引用

瀏覽器 JS 目前以傳統 script、全域函式或 `window` 模組載入，不是打包式 ES module。頁面順序先載入 vendor 與共用工具，再載入控制器；Functions 則使用 ES module import/export。新增或調整模組時核對實際載入頁面、全域名稱與依賴順序。

[output-utils.js](../../../js/shared/output-utils.js) 同時供傳統瀏覽器 script 與 Functions 打包器使用：瀏覽器先載入並提供 `OutputSafety`，再載入頁面控制器；Functions 由 [utils.js](../../../functions/_lib/utils.js) 匯入並提供 `escapeXml` 等相容入口。調整共用輸出行為時，須同時檢查 SSR 與瀏覽器測試，避免分別維護兩份相同規則。

`CategoryManager` 以 DOM 與回呼注入分類資料及更新通知；Slider 與 Lightbox 也由控制器提供元素與事件回呼。沿用適用介面即可，不要求為形式導入新的框架。

共用資料夾不等於已完成共用：目前裁切佇列與分類工具雖被頁面載入，主要控制器仍有自己的實作；批次頁也重複 Toast 與主題邏輯。整理前先核對輸出格式、圖片處理差異與狀態需求，不能直接刪除仍在使用的本地邏輯。

## 資料與輸出處理

- D1 沿用 Prepared Statement：使用者資料值透過 `bind()` 傳入，排序欄位與方向來自白名單；動態 IN 清單由佔位符與對應綁定組成。查詢結構與資料值分開處理，不把原始輸入當 SQL 片段。
- D1/R2 綁定由請求的 `env` 傳入；環境需求集中見 [建置、驗證與運維](../建置、驗證與運維/建置驗證與運維.md)。調整路由、認證或儲存格式時，同時核對外部配置與所有呼叫端。
- 將資料寫入 HTML、屬性、JSON-LD 或 URL 時，各自檢查對應輸出情境；沿用共用輸出工具，純文字、網址、數值與 script 邊界各自處理。描述支援範圍與實際契約見 [輸出安全](../功能、資料與契約/API與安全保護.md#輸出安全)。
- 管理頁與管理 API 放在 `/admin/` 的保護範圍內；變更路由時一併核對根 middleware、Access 目標、舊入口及部署別名，不只修改導覽連結。登入識別與憑證驗證的維護入口見 [API 與安全保護](../功能、資料與契約/API與安全保護.md)。
- 使用者可見文字、樣式及主題的目前狀態與擴充方向，見 [使用介面與內容](../使用介面與內容/使用介面與內容.md)。

## 驗證入口

自動測試以 `npm test` 執行，包含登入／輸出單位檢查及本機 Cloudflare 執行環境的瀏覽器整合；Functions 亦可獨立編譯。依改動範圍選擇必要驗證，不以語法或模擬環境通過代替正式站效果。環境、命令、已驗證範圍及限制集中見 [建置、驗證與運維](../建置、驗證與運維/建置驗證與運維.md)。
